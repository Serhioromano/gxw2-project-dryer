# Проект: ШУСК.080925 — Шкаф управления сушильной камерой (ПЛК Coolmay L02)

## Что это за проект

Разработка программы ПЛК для конвекционной сушильной камеры (сушка фруктов).
Платформа: **Coolmay L02** (совместим с FX3G), программирование — **GX Works 2,
IEC 61131-3 Structured Text (ST)**. HMI: **15″ сенсорная панель** (1024×768).

Система ведёт процесс сушки по программе из шагов (подъём → выдержка):

- 14 частотных преобразователей (ПЧ1–ПЧ14) циркуляционных вентиляторов;
- 1 ПЧ вентиляции/увлажнения (ПЧ ВЕНТ);
- 2 трёхходовых клапана подачи теплоносителя (4–20 мА, левый/правый) — нагрев;
- мониторинг 4 датчиков температуры в камере, 3 датчиков температуры продукта,
  влажности (ПВТ100), давления и протока воздуха;
- световая колонна (🔴/🟢/🟡 + зуммер), контроль перегрева ЩУ/СШ, РКФ, двери.

Два ПИД-контура: температура (нагрев → 3-ходовые клапаны) и влажность
(охлаждение → ПЧ вентиляции). Поддерживается автонастройка ПИД (autotune).

## Технический контекст

### Структура POUs (`ПО/`)

| POU | Тип | Назначение |
|---|---|---|
| `PRG_INIT` | Программа | Инициализация ПИД (R500/R600) и аварий (15 шт.) |
| `PRG_MAIN` | Программа | Автомат сушки: выбор шага, подъём/выдержка, ПИД, пауза по аварии |
| `PRG_PROCESS` | Программа | Чтение АИ, масштабирование, аварии, управление ПЧ |
| `ST_STEP` | Структура | Шаг: enable, rise/hold time, temp/humid, VFD speed |
| `ST_STEPHelper` | Структура | Состояние шага: idle/raise/hold/done |

### Адресация

**AI:**
- R23700–R23703 = 4× температура в камере (Pt100, модуль L02-RTD, готовое значение);
- R23704–R23706 = температура продукта 1–3;
- R23708 = давление, R23709 = влажность ПВТ100, R23710 = температура ПВТ100,
  R23711 = проток воздуха (все 4–20 мА, через SCALE к 0–32000);
- D8032/D8033 = обратная связь положения клапанов 1/2 (4–20 мА, 0–4000).

**AO:**
- D8052/D8053 = команда клапанов 1/2 (нагрев, 0–4000);
- R23500–R23514 = скорость ПЧ1–ПЧ14 и ПЧ ВЕНТ (по `плк.txt`).

**DI:**
- X00 = перегрев ЩУ (ошибка при наличии сигнала), X01 = РКФ (ошибка при отсутствии),
  X02 = перегрев СШ;
- X03–X12 = ошибка ПЧ1–ПЧ8, X20–X26 = ошибка ПЧ9–ПЧ14 и ПЧ ВЕНТ;
- X30 = дверь открыта.

**DO:**
- Y00–Y13 = запуск ПЧ1–ПЧ12, Y20 = ПЧ13, Y21 = ПЧ14, Y22 = ПЧ ВЕНТ;
- Y23 = колонна красный, Y24 = зелёный, Y25 = жёлтый, Y26 = звук;
- Y30 = сброс ошибок ПЧ.

### Аварии (15)

Через AlarmManager: 14× ошибка ПЧ (ПЧ1–ПЧ14) + 1× ошибка ПЧ ВЕНТ.
Входы перегрева (X00, X02), РКФ (X01) и двери (X30) заведены как DI-метки,
но в текущем коде к `FB_AM_SET` не подключены.

### Программа сушки

- До 5 шагов (`grSteps[0..4]`); шаг = подъём (`iRiseTime`) + выдержка
  (`iHoldTime`) с уставками `iHoldTempr` / `iHoldHumid` и скоростью `iVFDSpeed`.
- Автомат: Idle → выбор шага → Raise → Hold → следующий шаг → Done; Pause при
  блокирующей аварии (`FB_AM_IS_BLOCK`).
- ПИД температуры (R500, нагрев) → клапаны; ПИД влажности (R600, охлаждение) →
  ПЧ вентиляции. Автонастройка по флагам `gxPIDANTemp` / `gxPIDANHum`.

## Правила работы

1. **Привязки меток — в `ПО/IO.csv`** (источник истины по привязкам); `ПО/плк.txt`
   читать только для сверки привязок из IO.csv. Логика — в `ПО/*.iecst`.
2. Код — в `ПО/*.iecst`, один файл на POU; рядом CSV для импорта меток.
   Программа — ST для GX Works 2 (IEC), комментарии на русском.
3. Для написания кода и меток использовать скилл **`gxw2-st`**.
4. Расхождения и открытые вопросы фиксировать, а не «чинить» молча.
5. Не выходить за рамки ТЗ без согласования.
6. **Не коммитить** — коммиты делает пользователь вручную после ревью.
7. После изменений кода обновлять `README.md` (создать, если отсутствует).
8. При работе с библиотеками сверяться с документацией (таблица выше) — сигнатуры
   ФБ/функций, единицы времени, требования к лимитам устройств.
