# Сушильная Камера

Проект сушильной камеры для ковекционной сушки овощей и фруктов.

- ПЛК - Coolmay L02
- HMI - Coolmay TK8150

## Библиотеки

### AlarmManager (V213+)

Управление авариями (15 ошибок ПЧ).

- Хранилище объявлено в `ПО/GVL.csv`:
  - `AM_ALARMS : ARRAY [0..14] OF ST_AM_ALARM`
  - `AM_EVENTS : ARRAY [0..0] OF ST_AM_EVENT`
  - `c_AM_ALARMS_NUM = 14`, `c_AM_EVENTS_NUM = 0`
- Инициализация — `PRG_INIT` (`FB_AM_INIT`), регистрация — `PRG_PROCESS`
  (`FB_AM_SET`), сброс — `FB_AM_RESET`, блокировка — `FB_AM_IS_BLOCK` (`PRG_MAIN`).
- Упаковка состояний аварий в M-область: `fbAMPack(DNUM := 2000, PD := c_AM_PACK_M)`
  → авария N в `M2000+N` (совместимо с прежней развёрткой `BMOV D3280 → K4M2000`).

## Раскладка регистров D (ПО/GVL.csv)

Обмен с HMI/панелью в области неэнергонезависимых D-регистров (> D1000):

| Метка | Регистр | Назначение |
|-------|---------|------------|
| `giCS_Num` | D1000 | Текущий номер этапа |
| `giCS_RaiseETime` | D1001 | Истекшее время подъёма текущего этапа |
| `giCS_HoldETime` | D1002 | Истекшее время выдержки текущего этапа |
| `giCSVFDSpeed` | D1003 | Скорость ПЧ текущего этапа |
| `giCSTemp_SV` | D1004 | Уставка температуры текущего этапа |
| `giCSHum_SV` | D1005 | Уставка влажности текущего этапа |
| `giProbeType` | D1006 | Тип датчика температуры (0 - среднее, 1/2 - датчик) |
| `giPID_T_SV` | D1007 | ПИД температуры: уставка |
| `giPID_T_PV` | D1008 | ПИД температуры: текущее значение |
| `giPID_T_MV` | D1009 | ПИД температуры: выход (задание на клапаны) |
| `giPID_H_SV` | D1010 | ПИД влажности: уставка |
| `giPID_H_PV` | D1011 | ПИД влажности: текущее значение |
| `giPID_H_MV` | D1012 | ПИД влажности: выход (задание на вентилятор) |
| `giStart_T` | D1013 | Начальная температура для подъёма |
| `giStart_H` | D1014 | Начальная влажность для подъёма |
| `giRaiseET` | D1015 | Остаток времени подъёма, % (0-100) |
| `giHoldET` | D1016 | Остаток времени выдержки, % (0-100) |

## Открытые вопросы

- `giCSRaiseTime` и `giCSHoldTime` в `GVL.csv` указывают на те же `D1001`/`D1002`,
  что и `giCS_RaiseETime`/`giCS_HoldETime` — конфликт адресов, требуется решить.
- Массивы `grSteps` (5×6 INT) и `garstStepHelper` (5×1 INT) не привязаны к устройству;
  для `grSteps` в комментарии оставлена пометка «Назначить R1 как главный».
- `AM_ALARMS`/`AM_EVENTS` не привязаны к устройству — AlarmManager распределяет память автоматически.
