# Сушильная Камера

Проект сушильной камеры для ковекционной сушки овощей и фруктов.

- ПЛК - Coolmay L02
- HMI - Coolmay TK8150

## Графика (img/)

Иконки для HMI — фон экрана чёрный. SVG + PNG (256×256, прозрачный фон),
по одному файлу на состояние.

Вентилятор (центробежный, «улитка»):

| Файл | Состояние | Цветовая схема |
|------|-----------|----------------|
| `fan_inactive` | Не активирован (не в работе) | тёмно-серый, пунктирный контур, приглушённые лопасти |
| `fan_off` | Не работает (активирован, остановлен) | нейтральный серый, сплошной контур |
| `fan_on` | Работает | зелёный + пунктирное кольцо вращения |
| `fan_alarm` | Тревога | красный |

Клапан регулирующий (с приводом):

| Файл | Состояние | Цветовая схема |
|------|-----------|----------------|
| `valve_off` | Не работает | нейтральный серый |
| `valve_on` | Работает | зелёный + стрелки потока |

Сгенерированы скриптами (SVG-улитка с импеллером / клапан с приводом).

## Библиотеки

### AlarmManager (V213+)

Управление авариями (24 аварии: 15 ошибок ПЧ + 9 обрывов датчиков/клапанов).

- Хранилище объявлено в `ПО/GVL.csv`:
  - `AM_ALARMS : ARRAY [0..23] OF ST_AM_ALARM`
  - `AM_EVENTS : ARRAY [0..0] OF ST_AM_EVENT`
  - `c_AM_ALARMS_NUM = 23`, `c_AM_EVENTS_NUM = 0`
- Инициализация — `PRG_INIT` (`FB_AM_INIT`), регистрация — `PRG_PROCESS`
  (`FB_AM_SET`), сброс — `FB_AM_RESET`, блокировка — `FB_AM_IS_BLOCK` (`PRG_MAIN`).
- Упаковка состояний аварий в M-область: `fbAMPack(DNUM := 3000, PD := c_AM_PACK_M)`
  → авария N в `M3000+N`.
- Наличие любой аварии — `FB_AM_HAS_ALARMS` (`fbAmHas`) → `gxHasAlarm` (M439):
  TRUE, если зарегистрирована хотя бы одна авария (любой процесс/важность).

## Раскладка регистров D (ПО/GVL.csv)

Обмен с HMI/панелью в области неэнергонезависимых D-регистров (> D1000):

| Метка | Регистр | Назначение |
|-------|---------|------------|
| `giCS_Num` | D1000 | Текущий номер этапа |
| `giCS_RaiseETime` | D1001 | Истекшее время подъёма текущего этапа |
| `giCS_HoldETime` | D1002 | Истекшее время выдержки текущего этапа |
| `giCSVFDSpeed` | D1003 | Скорость ПЧ текущего этапа |
| `giCSTemp_SV` | D1004 | Уставка температуры текущего этапа |
| `giCSHum_SV` | D1005 | Уставка влажности текущего этапа |
| `giCSRaiseTime` | D1006 | Общее время подъёма текущего этапа |
| `giCSHoldTime` | D1007 | Общее время выдержки текущего этапа |
| `giProbeType` | D1008 | Тип датчика температуры (0 - среднее, 1/2 - датчик) |
| `giPID_T_SV` | D1009 | ПИД температуры: уставка |
| `giPID_T_PV` | D1010 | ПИД температуры: текущее значение |
| `giPID_T_MV` | D1011 | ПИД температуры: выход (задание на клапаны) |
| `giPID_H_SV` | D1012 | ПИД влажности: уставка |
| `giPID_H_PV` | D1013 | ПИД влажности: текущее значение |
| `giPID_H_MV` | D1014 | ПИД влажности: выход (задание на вентилятор) |
| `giStart_T` | D1015 | Начальная температура для подъёма |
| `giStart_H` | D1016 | Начальная влажность для подъёма |
| `giRaiseET` | D1017 | Остаток времени подъёма, % (0-100) |
| `giHoldET` | D1018 | Остаток времени выдержки, % (0-100) |

Состояния ПЧ (`giVFD1State`..`giVFD14State`, `giVFDVentState`) занимают
**D1020–D1034** — см. раздел «Состояния ПЧ».
Номер текущего этапа для HMI (`giCS_NumDisplay`) — **D1035**.
Остатки времени текущего этапа, мин (`giRaiseMinLeft`, `giHoldMinLeft`) —
**D1036–D1037** — см. раздел «Остатки времени этапа (мин)».

Времена шагов (`iRiseTime`, `iHoldTime`) задаются в **минутах** (счётчики
инкрементируются по `M8014` — 1-минутный импульс).

## Остатки времени этапа (мин)

Две глобальные переменные с остатком времени текущего этапа в минутах:

| Метка | Регистр | Назначение |
|-------|---------|------------|
| `giRaiseMinLeft` | D1036 | Осталось минут до конца подъёма текущего этапа |
| `giHoldMinLeft` | D1037 | Осталось минут до конца выдержки текущего этапа |

Считаются в `PRG_PROCESS` как `giCSRaiseTime − giCS_RaiseETime` и
`giCSHoldTime − giCS_HoldETime`, с ограничением снизу нулём. Это
минутные версии уже существующих процентных `giRaiseET` / `giHoldET`
(D1017 / D1018, `F_WORK_LEFT`).

Пока фаза не начата, показывается полное время фазы: во время подъёма
`giHoldMinLeft` = полная выдержка этапа, во время выдержки `giRaiseMinLeft` = 0.
В паузе (шаг 40) значения сохраняются на момент паузы.

## Состояния ПЧ (ПО/GVL.csv)

Каждый ПЧ имеет одно глобальное состояние (INT) из четырёх значений:

| Значение | Константа | Состояние |
|----------|-----------|-----------|
| 0 | `c_VFD_ST_NOT_ACTIVE` | Не активирован (нет разрешения `gxVFDn`) |
| 1 | `c_VFD_ST_STOPPED` | Не работает (разрешён, но выход ПЧ выключен) |
| 2 | `c_VFD_ST_RUNNING` | Работает (выход ПЧ включён) |
| 3 | `c_VFD_ST_FAULT` | В ошибке (активна авария ПЧ) |

Приоритет вычисления: ошибка → работает → не работает → не активирован.

| Метка | Регистр | ПЧ |
|-------|---------|----|
| `giVFD1State` | D1020 | ПЧ1 |
| `giVFD2State` | D1021 | ПЧ2 |
| `giVFD3State` | D1022 | ПЧ3 |
| `giVFD4State` | D1023 | ПЧ4 |
| `giVFD5State` | D1024 | ПЧ5 |
| `giVFD6State` | D1025 | ПЧ6 |
| `giVFD7State` | D1026 | ПЧ7 |
| `giVFD8State` | D1027 | ПЧ8 |
| `giVFD9State` | D1028 | ПЧ9 |
| `giVFD10State` | D1029 | ПЧ10 |
| `giVFD11State` | D1030 | ПЧ11 |
| `giVFD12State` | D1031 | ПЧ12 |
| `giVFD13State` | D1032 | ПЧ13 |
| `giVFD14State` | D1033 | ПЧ14 |
| `giVFDVentState` | D1034 | ПЧ вентиляции |

Состояния вычисляются в `PRG_PROCESS` (после формирования выходов ПЧ).
ПЧ вентиляции не имеет отдельного разрешения (`gxVFD`), поэтому состояние
`0` (не активирован) для него не используется.

## Клапаны (задвижки) — отображение на HMI

На каждый трёхходовой клапан (нагрев) — глобальный признак работы:

| Метка | Адрес | Тип | Назначение |
|-------|-------|-----|------------|
| `gxValve1Work` | M437 | BOOL | Клапан 1 в работе: `AO_Valve1 > 0` |
| `gxValve2Work` | M438 | BOOL | Клапан 2 в работе: `AO_Valve2 > 0` |

Вычисляются в `PRG_PROCESS` сразу после `AO_Valve1/AO_Valve2 := giPID_T_MV`.

Для отображения **положения** клапана доступны:
- фактическое положение (обратная связь 4–20 мА) — `AI_Valve1Position` /
  `AI_Valve2Position` (D11 / D12, `F_SCALE(D8032/D8033, …)`, 0–100);
- задание (команда) — `AO_Valve1` / `AO_Valve2` (0–4090, из `giPID_T_MV`).

> Ранее добавленные переменные `giValve1Pos` / `giValve2Pos` (по запросу
> «положение 0–100 из AO_ValveN») при ручной правке проекта удалены.

## Автомат сушки (`PRG_MAIN`)

Шаги автомата (`iStep`):

| Шаг | Назначение |
|-----|------------|
| 0 | Init — сброс `gxStart`, переход в Reset |
| 1 | Reset — обнуление счётчиков, уставок, признаков и состояний шагов |
| 2 | Idle — ожидание `gxStart` (пуск) |
| 10 | Step select — выбор текущего шага программы сушки |
| 20 | Raise — подъём температуры/влажности |
| 30 | Hold — выдержка |
| 40 | Pause — пауза |
| 50 | Finish — процесс завершён (`gxDone`) |

Переходы паузы/сброса выполняются до `CASE`, поэтому срабатывают из любого шага:

- `gxStart` = FALSE во время подъёма/выдержки (шаги 20/30) → шаг 40 (пауза),
  счётчики этапа (`giCS_RaiseETime` / `giCS_HoldETime`) и состояние шага сохраняются;
- `gxStart` = TRUE в шаге 40 → шаг 10, сушка продолжается с сохранённого места;
- `gxReset` (по переднему фронту, `MEP`) → шаг 0 → полный сброс программы;
- `gxNextStep` (кнопка «Следующий этап», по переднему фронту, `MEP`) во время
  подъёма/выдержки (шаги 20/30) → текущий этап помечается завершённым
  (`c_STATE_DONE`), `giStart_T`/`giStart_H` := уставки этапа, переход в шаг 10
  → автоматический выбор следующего этапа (или Finish, если он последний);
- блокирующая авария (`FB_AM_IS_BLOCK`) → шаг 40.

Признак паузы для HMI — `gxPause` (M436): TRUE, пока автомат находится в шаге 40.
В шаге 40 ПИД отключаются (`giPID_T_MV` = `giPID_H_MV` = 0), время этапа не считается.

Управляющие метки:

| Метка | Адрес | Назначение |
|-------|-------|------------|
| `gxStart` | M401 | Пуск: FALSE — пауза (шаг 40), TRUE — работа/продолжение |
| `gxReset` | M400 | Сброс: полный сброс программы (шаг 0 → 1 → 2) |
| `gxPause` | M436 | Процесс сушки на паузе (шаг 40) |
| `gxNextStep` | M440 | Кнопка «Следующий этап» (по фронту, шаги 20/30) |

## Открытые вопросы

- Массивы `grSteps` (5×6 INT) и `garstStepHelper` (5×1 INT) не привязаны к устройству;
  привязка задаётся вручную в GX Works 2 (в CSV не импортируется). Для `grSteps` в
  комментарии оставлена пометка «Назначить R1 как главный».
- `AM_ALARMS`/`AM_EVENTS` не привязаны к устройству — AlarmManager распределяет память автоматически.
- Сброс `gxReset` выполняется по переднему фронту (`MEP`): пока кнопка удерживается,
  повторных сбросов не происходит.
- Выход из паузы (шаг 40) — по `gxStart` при отсутствии блокирующих аварий. Если
  блокирующие аварии появятся, после их сброса при включённом `gxStart` сушка
  продолжится автоматически, без повторного нажатия ПУСК.
- Шаг 0 при сбросе выставляет `gxStart := FALSE`; если на HMI «Пуск» — фиксированный
  переключатель, после сброса его состояние нужно снять и подать заново.
- `giCS_NumDisplay` (D1035) в `ПО/GVL.csv` имеет комментарий, скопированный
  от переменных состояния ПЧ («Состояние ПЧ: …»), а не описывающий её назначение.
  Требуется поправить комментарий (значение вычисляется в `PRG_PROCESS`:
  `SEL(gxProgress, 0, giCS_Num + 1)` — номер этапа для HMI).
- Кнопка «Следующий этап» (`gxNextStep`) действует только в шагах 20/30
  (подъём/выдержка). В шаге 40 (пауза) нажатие игнорируется — сначала нужно
  снять/подать ПУСК. Уточнить, нужно ли завершать этап и из паузы.
